## Что исправить или подтвердить прежде всего

1. **Сохранения: п. 1.9 и сохранение гостевого прогресса по 1.2.2 — высокий риск потери данных.**
   - `Assets/plugins/PluginYourGames/Platforms/YandexGames/Plugins/YandexCloudSave.jslib:9`: при отсутствии SDK запись просто прекращается. Ошибка Promise только выводится в консоль. Нет локальной копии, очереди и повтора.
   - В том же файле, строки 23–30: ошибка чтения и отсутствие данных возвращают одинаковую пустую строку.
   - `Assets/scripts/YandexCloudSave.cs:11`: после шести секунд ожидания чтение также завершается пустыми данными. `PlayerPrefs` используется только вне WebGL.
   - `Assets/scripts/YandexPlayerData.cs:30`: пустой результат становится новым профилем; миграция вызывает `Save()`. При восстановлении связи это создаёт риск перезаписи существующего облачного прогресса стартовым профилем. Это вывод из цепочки кода; перезапись реального аккаунта не выполнялась.
   - Каждый запрос записи снова вызывает `getPlayer()`. По документации его лимит — 20 вызовов за пять минут; для `setData()` — 100. Покупки и начисления денег могут вызвать повторные сохранения достаточно часто. Нужны кеширование Player, последовательная отправка, обработка ошибок и защита от записи после неуспешной загрузки. [Данные игрока](https://yandex.ru/dev/games/doc/ru/sdk/sdk-player).
   - Изолированная проверка реального JS-моста в Node: успешный SDK возвращает JSON; отсутствующий SDK и отклонённый запрос возвращают пустую строку, а запись не сохраняется. Проверка не обращалась к Яндексу и не меняла аккаунт.

2. **Пропорции игрового поля: п. 1.6.2.2 — не обеспечены.**
   - `Assets/WebGLTemplates/YandexGames/style.css:22`: контейнер и canvas занимают 100% ширины и высоты; ограничения соотношения сторон нет.
   - `Assets/plugins/PluginYourGames/Resources/SettingsYG2.asset:51`: `fixedAspectRatio: 0`.
   - Такой же CSS находится в проверенном ZIP. Например, при доступной области 2560×1080 соотношение получается 2,37:1. Нужно ограничение до 2:1 или фиксированное игровое поле 16:9 с полями снаружи. Это расчёт по CSS, не результат запуска игры на широком мониторе.

3. **Устройства и управление: п. 1.6.1.5, 1.6.3.2–3, 1.10.4.**
   - Движение использует `Keyboard.current` (`PlayerController.cs:94`), обзор — `Mouse.current` (`PlayerCameraLook.cs:108`). Сенсорного управления и управления с ТВ-пульта в игровом коде не обнаружено. Мобильные устройства и ТВ сейчас заявлять нельзя.
   - Буквальное требование управления одной рукой не выполняется стандартной схемой WASD + мышь. Исключение для такого FPS в проверенных правилах не найдено; нужно согласовать применимость с модерацией либо предусмотреть соответствующую схему управления. [Разъяснение п. 1.10](https://yandex.ru/dev/games/doc/ru/requirements/1/10).
   - Приседание назначено также на Ctrl. Одновременное движение W/S может конфликтовать с браузерными Ctrl+W / Ctrl+S: риск по 1.6.2.6, требующий браузерной проверки. Альтернатива C уже есть; безопаснее убрать Ctrl для WebGL.

4. **Монетизация: п. 1.12 — зависит от оформления черновика.**
   - В игровом коде не обнаружены вызовы рекламы или SDK-покупок. Магазин оружия использует заработанную игровую валюту, это не инап-покупки за деньги.
   - Наличие примеров рекламного API внутри плагина не означает интеграцию рекламы в игру.
   - Нужно подключить рекламу/инапы либо прямо указать в комментарии разработчика, что монетизация не предусмотрена. Стартовая реклама платформы не засчитывается. [Официальное разъяснение](https://yandex.ru/dev/games/doc/ru/requirements/1/12).

5. **Инструкция по управлению: п. 2.2 — не подтверждён.**
   - Полное обучение/экран управления в собственных скриптах и переводах не найден. Управление должно быть описано в игре или в поле «Как играть» в консоли; содержимое поля неизвестно.
   - Описание должно охватывать движение, обзор, стрельбу, прицеливание, бег, прыжок, приседание/скольжение, перезарядку, смену оружия, гранату и навыки.

6. **Сетевой режим: п. 1.14 — прежняя CSP-проблема требует повторной проверки на площадке.**
   - Есть ранее зафиксированная блокировка Photon-сервера `exitgames.com`; успешное подключение после изменения правил не подтверждено.
   - Локально проверить действующие заголовки CSP черновика нельзя. Нужен вход в комнату двумя клиентами с площадки. Подробности: [предыдущая проверка подключения](yandex-deployment-settings.md).
