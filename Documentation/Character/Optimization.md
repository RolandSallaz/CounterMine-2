# Проверка производительности и визуальные изменения

Изменения по результатам чтения текущего кода:

- Проверки укрытий используют RaycastNonAlloc с буфером на 64 результата. Если буфер заполнен, используется RaycastAll, чтобы не потерять ближайшую стену. Фильтрация собственных коллайдеров и отдельный расчёт хитбоксов сохранены.
- PlayerHealth сохраняет ссылку на PlayerHitboxes; классификация костей по именам выполняется при инициализации вместо каждого снимка позы.
- Боты проверяют видимость раз в 0,15 с. Для обхода стен используются физические коллайдеры, без перебора истории хитбоксов всех игроков. Массив углов обхода общий; неудачный поиск маршрута повторяется с паузой. Баллистика всё равно проверяет реальные препятствия при каждом шаге полёта.
- Удаление тел ботов проверяется раз в 0,25 с, коллекции переиспользуются. Ранее поиск объектов и создание трёх коллекций происходили каждый кадр.
- Числа урона используют пул с максимумом 30 отображаемых объектов. Цвет обычного урона белый, критического — янтарный.
- Искры отключаются один раз по завершении эффекта. Следы попаданий плавно исчезают за последние 1,5 с; для этого материал использует прозрачность. Количество следов ограничено прежним пулом.
- Скрытый прицел не пересчитывает геометрию. Стамина обновляет полосу только при изменении значения и плавно меняет цвет возле низкого остатка.
- Исправлена досягаемость рукояток в подкате; максимальная ошибка проверенных поз — 0,007442 м.

Проверки Unity: насыщенный запрос с 80 коллайдерами, фильтрация собственных коллайдеров, ближайшая преграда, пустой луч, лимит и переиспользование 30 чисел урона; проверки запуска подката/стамины/потолка и 48 поз приседа/подката. Отчёты — query_optimization_validation.txt и slide_crouch_validation.txt.

Это не замер FPS. Счётчик GC.GetAllocatedBytesForCurrentThread в запущенной версии Unity вернул нули и для исходного RaycastAll, поэтому численную оценку выделений памяти по нему получить нельзя. Полёт пуль и сетевое управление двумя клиентами требуют отдельного игрового прогона.

Следующий осмысленный шаг — профиль CPU/GPU в WebGL-сборке с шестью ботами и стрельбой, затем работа с подтверждённым ограничением (анимация/скиннинг, тени или физика). Параметры качества изображения вслепую не снижались. Для WebGL уже выбран профиль Mobile с Render Scale 0,8; PC использует масштаб 1 и четыре каскада теней.
